# Claude Context Monitor

**Claude Code의 컨텍스트와 한도를 macOS 메뉴바에서.** · [English](README.md)

실행 중인 각 세션의 컨텍스트 창이 얼마나 찼는지, 5시간·7일 한도를 얼마나 썼는지
보여주고, 세션이 가득 차기 전에 경고합니다.

> 제가 필요해서 Claude Code로 만들었습니다. 세션을 여러 개 띄워놓고 쓰다 보니
> 어느 세션이 컨텍스트를 다 써가는지 알 방법이 없어서, 없는 도구를 Claude Code에
> 시켜 만들고 실제 환경에서 검증했습니다. 아래 지원 범위 표는 추정이 아니라 실제로
> 테스트한 결과입니다.

![드롭다운](docs/menu.png)

```
⚡ ▸26% · 2/3 ◌1   7d 42%
```

| 부분 | 뜻 |
|---|---|
| `▸` | 지금 보고 있는 터미널 탭의 세션을 따라가는 중 — 없으면 가장 많이 찬 세션을 표시 |
| `26%` | 그 세션의 컨텍스트 창 사용률 |
| `2/3` | 3개 중 2개 동작 중. 상태를 보고하는 세션만 셉니다 |
| `◌1` | 동작/유휴를 알 수 없는 세션 1개 |
| `7d 42%` | 주간 한도 사용률 |

각 세션의 하위 메뉴에서 세션 id나 `claude --resume` 명령 복사, 작업 디렉터리 열기,
transcript 위치 열기를 할 수 있습니다.

## 요구사항

- macOS 13 이상
- Claude Code (`~/.claude/sessions/`를 기록하는 최근 버전)
- Swift 컴파일러용 커맨드라인 도구: `xcode-select --install`

## 설치

```sh
git clone <이 저장소> claude-context-monitor
cd claude-context-monitor
./install.sh
```

앱을 빌드해 `~/Applications`에 설치하고, 로그인 시 자동 실행하도록 등록하며,
Claude Code의 status line을 번들 안의 수집기로 연결합니다.
**클론한 디렉터리는 설치 후 지워도 됩니다** — 아무것도 그곳에서 실행되지 않습니다.

macOS가 두 가지 권한을 물어봅니다. 둘 다 선택 사항입니다:

- **알림** — 임계값 경고용
- **자동화** — 어느 터미널 탭이 앞에 있는지 읽을 때 최초 1회. 거부하면 `▸` 포커스
  표시만 사라지고 나머지는 그대로 동작합니다.

업데이트는 pull 후 `./install.sh`를 다시 실행하면 됩니다. 제거는:

```sh
./uninstall.sh
```

제거 시 원래 쓰던 status line을 복구하고, 앱·런치에이전트·캐시를 지우며,
`~/.claude`와 직접 작성한 푸시 스크립트는 건드리지 않습니다.

## 환경별 동작 범위

| | 세션 목록 | 컨텍스트 | 5h / 7d 한도 | 경고 | 포커스 `▸` |
|---|---|---|---|---|---|
| **iTerm2** *(검증됨)* | ● 동작 / ○ 유휴 | 정확 | 됨 | 됨 | **됨** |
| **PyCharm 터미널** *(검증됨)* | ● 동작 / ○ 유휴 | 정확 | 됨 | 됨 | 안 됨 |
| **Claude 데스크톱 앱** *(검증됨)* | ◌ 불명 | 추정 | **단독으로는 안 됨** | 됨 | 안 됨 |
| 기타 터미널 — Terminal.app, Ghostty, Warp, WezTerm, VS Code | 될 것으로 예상 | 정확 | 됨 | 됨 | Terminal.app만 |

제약이 생기는 이유:

- **포커스 추적**은 앞에 있는 앱에게 "어느 탭이 앞이냐"를 물어봅니다. 이에 답할 수
  있는 것은 iTerm2와 Terminal.app뿐이라, 나머지 환경에서는 가장 많이 찬 세션을
  보여주는 방식으로 대체됩니다. 다른 기능은 영향을 받지 않습니다.
- **데스크톱 앱**은 다른 세션과 똑같이 레지스트리에 등록되지만 status 필드를 쓰지
  않습니다. 그래서 동작/유휴를 추측하지 않고 "불명"으로 표시하며 `2/3` 비율에서
  제외합니다. 컨텍스트는 status line 대신 transcript에서 읽으므로 근사치입니다.
- **한도에는 터미널 세션이 하나 필요합니다.** 한도 수치는 status line을 통해서만
  들어오는데 데스크톱 앱은 이를 렌더링하지 않습니다. 수치 자체는 계정 단위라 이미
  데스크톱 사용량까지 포함하지만, 데스크톱 앱만 켜두면 갱신이 멈추고 드롭다운이
  해당 시각을 주황색으로 표시합니다.

## 설정

모두 메뉴 안에 있습니다.

| 항목 | |
|---|---|
| **Alerts** | 경고 기능 전체, 세션 컨텍스트와 주간 한도 개별, 임계값, 푸시 스크립트 |
| **Follow focused terminal** | `▸` 동작 끄기. 끄면 항상 가장 많이 찬 세션을 표시 |
| **Refresh every** | 전체 갱신 주기 1 / 3 / 5 / 10분 |

갱신 주기는 **전체 갱신**에만 해당합니다. 컨텍스트 사용량과 동작/유휴 상태는 파일
감시로 반영되어 주기와 무관하게 1초 안에 따라옵니다.

## 경고

시끄럽지 않게 설계했습니다. 각 단계는 세션당 한 번만 울리고, 사용률이 가장 낮은
임계값 아래로 떨어져야 다시 무장합니다. 82%에 머무는 세션은 매분이 아니라 한 번만
알립니다. 기본 임계값은 80 / 90 / 95%입니다.

### 푸시 스크립트

경고를 원하는 실행 파일에 넘길 수 있습니다 — **Alerts → Push script…**, 또는 기본
경로인 `~/.claude/widget-notify`에 스크립트를 두면 됩니다. 이것이 확장점입니다.
앱 자체는 네트워크 요청을 하지 않으므로, 이 맥을 떠나는 것은 전부 사용자가 작성한
스크립트를 통과합니다.

경고마다 한 번 호출되며 `$1`로 메시지를, stdin으로 JSON 객체를 받습니다:

```jsonc
{
  "kind": "context",            // "context" | "limit"
  "level": 90,                  // 넘어선 임계값
  "percent": 91,                // 발화 시점 실제 사용률
  "message": "context 91% · V3 설계",
  "at": 1789109038,             // unix 초
  "session": {                  // "context"일 때만
    "id": "0c972047-…",
    "name": "V3 설계",
    "cwd": "/Users/you/project",
    "model": "Opus 5 (1M context)",
    "entrypoint": "cli",        // "cli" | "claude-desktop" | …
    "tokens": 912345,
    "window": 1000000
  }
}
```

```jsonc
{
  "kind": "limit",
  "level": 80,
  "percent": 85,
  "window": "seven_day",
  "resets_at": 1789113600,      // unix 초
  "message": "weekly limit 85% used",
  "at": 1789109038
}
```

`$1`만 필요하면 stdin은 무시해도 됩니다. 페이로드는 파이프 버퍼에 들어가는 크기라
stdin을 읽지 않는 스크립트도 멈추지 않습니다:

```sh
#!/bin/sh
curl -fsS --max-time 5 -d "$1" https://ntfy.sh/your-topic
```

맥 배너는 애플워치로 전달되지 않습니다. 이 기능은 그 간극을 메우기 위한 것입니다.

## 동작 원리

전부 로컬에서 이뤄집니다. 자격증명을 읽지 않고 네트워크 요청도 하지 않습니다.

- **`~/.claude/sessions/*.json`** — 세션 레지스트리. pid, 이름, 디렉터리,
  동작/유휴가 들어 있습니다. 파일 시스템 이벤트로 감시하므로 상태 변화가 갱신
  주기를 기다리지 않고 1초 안에 반영됩니다.
- **status line** — Claude Code는 렌더링할 때마다 status line 스크립트에 자신의
  수치를 넘겨줍니다: `rate_limits.five_hour`와 `.seven_day`, 컨텍스트 사용량,
  모델, 비용. `cc-widget-statusline`이 이를 `~/.claude/widget-cache/`에
  캐시합니다. 한도를 얻을 수 있는 유일한 수동적 경로입니다 — 다른 곳에 저장되지
  않으며, 다른 방법으로 읽으려면 키체인에서 OAuth 토큰을 꺼내야 합니다.
- **`~/.claude/projects/*/*.jsonl`** — transcript. status line을 만들지 않는
  세션에 한해서만 읽습니다. 각 파일의 앞뒤 일부만 파싱하므로 40MB짜리 기록도
  작은 파일과 비용이 같습니다.

이미 status line을 쓰고 있었다면 install.sh가 이를 보존합니다. 기존 명령을
저장해두고 수집기가 그것을 실행해 출력을 그대로 통과시킵니다.

## 커맨드라인

앱이 같은 내용을 텍스트로 출력합니다:

```sh

```

## 문제 해결

**아이콘이 안 보입니다.** Vanilla·Bartender·Ice 같은 메뉴바 관리 도구가 숨김
영역에 넣었을 수 있습니다. `⌘`을 누른 채 아이콘을 구분자 오른쪽으로 끌어다
놓으세요. 위치는 기억됩니다.

**`▸`가 전혀 안 뜹니다.** 앞에 있는 터미널이 iTerm2나 Terminal.app이 아니거나,
자동화 권한이 거부된 경우입니다 — 시스템 설정 → 개인정보 보호 및 보안 → 자동화.
재빌드하면 ad-hoc 서명이 바뀌므로 업데이트 후 다시 물어볼 수 있습니다.

**한도가 "no data yet"이거나 주황색입니다.** 한도는 터미널 세션이 status line을
렌더링하는 동안에만 갱신됩니다. 터미널 세션을 하나 열어두거나, 데스크톱 앱만 쓰는
동안에는 마지막 값이 유지된다는 점을 감안하세요.

**세션이 `◌`로 표시됩니다.** status 필드 없이 등록된 세션입니다 — 데스크톱 앱이
이렇게 동작합니다. 상태를 정말로 알 수 없으므로 추측하지 않고 그대로 표시합니다.

## 구성

```
src/app.swift          메뉴바 앱
src/statusline.swift   status line 수집기
build.sh               둘 다 빌드해 build/ClaudeContextMonitor.app 생성
install.sh             빌드·설치·로그인 등록
uninstall.sh           전부 되돌리기
```
